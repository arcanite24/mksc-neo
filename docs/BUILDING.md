# Building, testing and running

## Build and check

Use CMake 3.20+, a C11 compiler and Python 3. SDL builds also need an installed SDL3 CMake package. The maintained SDKs use SDL 3.4.18; Windows uses an x64 Visual Studio developer prompt. Point `CMAKE_PREFIX_PATH` at your SDL install if it is not found automatically.

```sh
python3 tools/portable/check.py debug
python3 tools/portable/check.py all
python3 tools/portable/check.py debug --sdl --rom path/to/mksc.gba
# Reuse an already imported pack instead of importing:
python3 tools/portable/check.py debug --sdl --game-pack .mksc-tools/portable/packs/game.pack
```

`all` runs debug, release and sanitizer profiles; MSVC supports debug/release only. `--test REGEX` narrows the CTest run (CTest still adds fixture dependencies); no matches is an error. Run debug before committing; run all and the SDL suite before a release. Checks keep builds/logs under `.mksc-tools/portable/check/`, treat project warnings as errors and run the whole headless CTest suite as one command with one job per CPU (`--jobs N`), at most four real-device GPU routes at once (`--gpu-slots N`), reporting every failure. Never run two checks/builds against the same shared build directory. Virtual-pad tests do not establish physical controller usability.

SDL_GPU scene shaders are authored in `portable/platform/shaders/` and embedded as DXIL, SPIR-V and MSL source. The player needs no shader compiler. Rebuild on macOS (arm64/x64), Windows/Linux x64 with `python3 tools/portable/build_render_shaders.py --bootstrap .mksc-tools/portable/tools/render-shaders --work .mksc-tools/portable/runs/t2/shaders`; the tool pins DXC v1.8.2505.1 (Gaijin's matching macOS library plus the offline CLI adapter on Mac) and SPIRV-Cross vulkan-sdk-1.4.313.0 with archive hashes. Repeat with `--dxc PATH --spirv-cross PATH --tool-lock CACHE/tools.json --check` to compare generated bytes. `--verify-sources` checks the embedded source hash without compilers; `--self-test` exercises tooling validation.

`portable_render_gpu` uses a real SDL_GPU device with an offscreen renderer and no window. Its video backend permits device creation; `dummy` cannot establish GPU acceptance. Missing devices explicitly skip the unit test. A driver-named PASS establishes the tested backend's rendering correctness; display-rate and handheld acceptance remain separate gates.

The existing mesh route harness accepts `--world-scale 4 --views 1|4 --interpolated
--benchmark` with its GPU/GLES probe. It first checks ordinary captured racing/results
and saved replay, then performs a separate capture-free run: 64 warmups, 300 complete
composed frames and 19 completion barriers. Logs distinguish CPU submission time
from completed offscreen batch wall time (including intervening shell/simulation work).
CPU submission includes world preparation, the configured 320×180 accelerated UI, composition
and present. `portable_render_gpu_tests --ui-benchmark` compares warmed equal-resolution setup frames (720p/4K) with CPU fallback, with GPU validation off only for timing. Neither capture-free measurement establishes physical display pacing;
WSL GLES on Mesa's D3D12 bridge is also distinct from native Linux GPU acceptance.

## Import, launch and controls

The owner supplies Mario Kart: Super Circuit (US), SHA-1 `9d327c030c3e2d9007990518594f70c3340ac56f`. No ROM or imported assets ship in the source or player bundle. The SDL executable is `.mksc-tools/portable/check/debug-sdl/mksc` (`mksc.exe` on Windows):

```sh
.mksc-tools/portable/check/debug-sdl/mksc --import path/to/mksc.gba .mksc-tools/portable/packs/game.pack
.mksc-tools/portable/check/debug-sdl/mksc .mksc-tools/portable/packs/game.pack
```

`MKSC_STARTUP_TIMING=1` logs launch-to-first-loading/menu-frame and pack, mod, 3D browser, GPU, menu shader/font and texture-upload phases. Startup and mod Apply/Reload show an animated loading screen with stage progress; Esc/B cancels preparation and preserves active mods, and closing waits for worker cleanup while continuing to pump events. `MKSC_SCREEN_DIR` with timing enabled also captures `startup-loading.ppm`.

Without a pack argument the first-start screen accepts a ROM (`.gba`, or a `.zip` containing it) through its dialog or file drop and imports into the data folder on a worker thread; the first import then shows a short Before You Race page (display, drift extras, menu style) saved to `settings.json`, and the game starts. An older importer stamp offers reimport from the remembered ROM or keeping the existing pack. Native import requires no Python. The reference command `python3 tools/portable/import_rom.py --rom ROM --compare PACK` verifies section bytes; `--compare-binary MKSC` exercises native import. `check.py --rom` includes importer equality.

Mario Kart DS (US) content becomes the `mario-kart-ds` folder mod through Options > Mods > Import from another game (`.nds`, a `.zip` containing it, or a dropped `.nds`), or headless with `mksc --import-game ROM [MODS_DIR]`. `check.py --mkds-rom workspace/mkds/baserom.nds` adds its checks (the Mods tab tours also need `--sdl --rom`). `tools/portable/nds_inspect.py list|extract|text ROM ...` reads DS ROMs into `.mksc-tools/portable/runs/nds-inspect/`. Mario Kart 64 (US) uses the same menu/CLI and produces `mario-kart-64`: `.z64`, `.v64`, `.n64` (detected by bytes) or ZIP, normalized and SHA-1 checked. Its 16 courses race in TT, GP (the four source cups), Quick Run and VS; the four battle stages fight from the original starts; scenery, vehicles, scrolling water, skies and the eight racers (as sprite drivers on the second character page) come along. Enable the mod and pick its cups on the course screen (L/R). `check.py debug --mk64-rom ROM --test portable_mk64 --jobs 4` adds owner-ROM checks (with `--sdl --rom`, an aided TT and GP).

Keyboard defaults: arrows drive, Z also accelerates, Shift hops, C uses an item, Up/Down aims, Tab honks, X rescues, P/Space pauses. Enter confirms menus, Esc backs out. On a standard pad: South accelerates/confirms, East brakes/backs out, stick/D-pad steers, right shoulder hops, left shoulder uses an item, West rescues, Back honks and Start pauses. Cup selection uses shoulders or Tab to change track sets. Options edits video/audio/enhancements; confirm the Stick Deadzone row to edit bindings. Menu bindings stay fixed. Local multiplayer selects 2–4 players; more than two require pads.

Each choice keeps its existing separate progress, records and ghosts; switching validates target saves first. Real modern physics belongs to 3D mesh courses and their authored physics profile. `--drift-extras off|tiers|tiers-air-boost` temporarily overrides the 2D choice. The compatibility aliases `--driving-profile original|modern|modern-air` still select the same stored values, identities and saves. Recorded replays select their existing profile from the header and still require matching content and rules. GP shells and bananas retain hold-Item-to-drag, release-to-fire controls in every choice.

Menus default to the modern full-resolution style; Menu Style in Enhancements, `classic_menus` in `settings.json` or `--classic-menus` restores the original 240×160 menus (which keep source transition timing unless Short Transitions is on). In modern Options, L/R (A/S keys or shoulders) switch between Game, Controls, Enhancements, Mods and Games. Games lists the base game and the importable source games (Mario Kart DS and Mario Kart 64) and stages per-category asset sources (see Modding). The Mods tab uses the same full-resolution presentation; Classic menus retain the original manager. Modern results use the same style over a frozen race in TT, GP, Quick Run, VS and Battle, including ghost saving and GP points/standings; the existing confirmation and ghost controls still apply.
Modern loading/course cards and short race/results/ceremony reveals reuse existing clocks; they add no race ticks or input locks. Classic menus keep their original transitions.

In a race, Select (Tab on the keyboard) on the pause menu opens a Graphics page with the Options rendering rows (Fullscreen, Window Scale, VSync, Filter, Display Scaling, Aspect Ratio, Internal Scale, Interpolation, Render FPS, Race Renderer, HD-2D Graphics). Edits use the Options code, apply at once to the paused race (Race Renderer and local-multiplayer scale/aspect wait for the next race) and save like Options; B closes the page. On the classic course page a mod course or cup name wider than its window scrolls instead of being cut.

Options save immediately. Boolean switches have inverse forms; `mksc --help` lists the full CLI. Default transitions retain source timing; Short Transitions allows early GP board/ceremony confirmation. See [Modding](MODDING.md) for content flags.

Enhancements always lists every option, including Race Renderer after Artwork
Detail. Original remains the default. 3D renders the course as textured flat
geometry with depth-tested world sprites, using the same race rules and saves.
`--race-renderer original|3d` overrides the selection for one launch. Unsupported
scenes show an Original-renderer fallback notice; malformed assets still fail.
On the modern page, 3D Effects switches every 3D race effect between Full and Low
Power; the rows below it toggle each one (`--[no-]smooth-3d`, `--[no-]dynamic-camera`,
`--[no-]camera-shake`, `--[no-]drift-sparks`, `--[no-]boost-effects`, `--[no-]kart-trails`).

Modern Enhancements also offers **HD-2D Graphics: Off / Extra Juicy / Custom** for SDL_GPU worlds. Extra Juicy enables Tilt-Shift, Bloom, Ambient Occlusion (SSAO-lite), Color Grading, Atmospheric Haze, Sprite Lighting and High 3D Resolution (minimum 6x, 960 vertical pixels per view row). All seven default off and save independently. The post pass precedes the HUD, clamps samples to each split view and leaves CPU/GLES/Original paths unchanged. High resolution costs extra fill and memory; the regular Internal Scale remains untouched. `--[no-]hd2d-dof`, `--[no-]hd2d-bloom`, `--[no-]hd2d-ao`, `--[no-]hd2d-grade`, `--[no-]hd2d-fog`, `--[no-]hd2d-light`, `--[no-]hd2d-scale` override individual choices. Haze is depth fog, not volumetric ray marching; existing soft kart shadows remain. `build_render_shaders.py --post` rebuilds the finish shader with the same tool arguments; `--post --verify-sources` checks it. `portable_render_gpu_tests --hd2d-benchmark` measures warmed 720p individual effects and reports completed workload time (CPU submission plus GPU completion, not GPU timestamp queries).

Optional mod models replace supported kart/scenery poses in 3D; missing model
assets or pose variants retain the source billboards. See [Modding](MODDING.md)
for the low-poly example and JSON/OBJ authoring.

Mesh course mods add their cups to the ordinary course screen: L/R steps past the 2D sets to one
cup row per providing mod (e.g. **Mario Kart DS**), Battle included. A mod that provides both courses and drivers is a content platform (Mario Kart DS, Mario Kart 64): its drivers fill their own character pages, named by the pills above the grid, and picking one limits the course screen to that platform's cups, the rivals to its drivers and the other local players to its pages; Super Circuit drivers race the 2D sets and platform-free 3D mods. Confirm races the course in the
selected mode (GP only lists complete four-course cups); Select on a course explores it. This format is separate from the flat optional Race Renderer. Build the ROM-free
bridge example and enable it in Mods as described in [Modding](MODDING.md). App/APK updates preserve installed mod data: rebuild and reinstall 3D mod ZIPs to pick up revised default physics and gravity; existing compiled packs retain their authored values and records.
Local 3D VS/Battle uses independent inputs and cameras for two to four humans, with shared
pause, standings, Retry and Change course. The last unfinished racer is ranked

3D records and ghosts live under `mesh3d/`, separate from recovered 2D saves.
Verify a saved 3D ghost with `mksc --mesh-finished-replay PACK GHOST
--mods-dir MODS --mod ID`; the exact recorded content must be enabled.

Local VS and Battle use the same saved aspect, internal resolution,
interpolation and render-rate settings for each player's view. A fixed aspect
applies to each pane; Auto follows that pane's window area as the window is

Data folders: macOS `~/Library/Application Support/MKSC Neo/Portable/`; Linux `~/.local/share/MKSC Neo/Portable/`; Windows `%APPDATA%\MKSC Neo\Portable\`. `MKSC_DATA_DIR` overrides the location. Settings, pack, records, ghosts and `mods/` live there; modded and mirrored records retain their own identities. Browser saves last only for the current page session.

Ghosts retain the original 4 KiB input-stream budget in every 2D Drift Extras choice. An exhausted recording cannot be saved as a ghost; native input replays use their separate extended state format.

## Player bundles

Run `python3 tools/portable/package_release.py --sdl-prefix PREFIX --rom ROM`; archives appear in `.mksc-tools/portable/runs/dist/`. Rescan with `--check ARCHIVE --rom ROM`. Bundles contain the executable, SDL and notices; the content scan rejects game assets and scans ROM fragments/encoded tables. It does not establish licensing of transformed artwork. Imports and saves belong in the data folder.

Releases are built by `.github/workflows/release.yml`. Pushing a tag `vMAJOR.MINOR.PATCH` (or `vX.Y.Z-rc.N`, published as a prerelease) runs the headless tests, builds the macOS, Linux, Windows, web and Android bundles and publishes them with `SHA256SUMS.txt` as a GitHub release. Running the workflow by hand builds the same bundles as workflow artifacts without publishing. Android APKs are signed with the repository secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` and `ANDROID_KEY_PASSWORD`; without them they are debug-signed. Locally, `android.py --release` signs with `MKSC_KEYSTORE`, `MKSC_KEYSTORE_PASSWORD`, `MKSC_KEY_ALIAS` and `MKSC_KEY_PASSWORD` when set.

macOS bundles target 11+ with arm64/x86_64 and ad-hoc signing; Control-click → Open may be needed. Windows bundles use a static CRT, GUI executable and default 1 MiB stack. Linux bundles built with the maintained Sniper SDK target x86_64/glibc 2.31+ and carry SDL beside the executable. Packaging does not publish or notarize. A universal build alone does not prove Intel execution.

## Other backends

Android (arm64, API 26+) builds with the Android SDK, NDK 27.1, JDK 17 and the SDL 3.4.18 source tree, whose `android-project` supplies the Gradle wrapper and SDL's Java activity. The game builds as `libmksc.so`; Gradle output stays under `.mksc-tools/portable/check/android/`:

```sh
python3 tools/portable/android.py --sdl-source PATH/SDL3-3.4.18            # APK only
python3 tools/portable/android.py --sdl-source PATH/SDL3-3.4.18 --run      # install, launch, follow the log
```

Debuggable APKs take desktop arguments and aid environment through the launch intent, for example `am start -n io.github.mkscneo/.MkscActivity --esa args --menu-tour,PACK,SAVE,SCRIPT --esa env MKSC_AID_GLES=1,MKSC_STDIO_LOG=FILE` (paths inside the app's `files/`, staged with `run-as`); `MKSC_STDIO_LOG` receives stdout/stderr.

The app is always fullscreen and landscape, races default to auto aspect with Fit scaling, and modern menus use native-resolution SDL_GPU or GLES geometry (CPU fallback is capped); the first start opens the system file picker (tap the drop zone or press A) and imports into the app's private data folder. Controllers use the standard pad mapping.

Game options includes Touch Controls (off by default), also available through
`--touch-controls`/`--no-touch-controls`. The pad drives menus and Player 1;
hold A, a direction and HOP together to accelerate, steer and hop. ITEM uses
items, START pauses, and SEL honks or performs the menu's Select action.
Android Back goes back in menus, opens pause during a race and selects Continue
from pause. After backgrounding, a race stays paused when the app returns;
resume explicitly. Suspended touches are cleared so fingers cannot stay held.

PowerPC/i686 Linux builds require their GCC/libc SDK and QEMU user emulation. For each target, run sequentially:

```sh
build="$PWD/.mksc-tools/portable/runs/portability/powerpc" # or i686
cmake -S portable -B "$build" -DCMAKE_BUILD_TYPE=Debug -DPORTABLE_BUILD_SDL3_APP=OFF -DPORTABLE_STRICT_WARNINGS=ON -DCMAKE_TOOLCHAIN_FILE="$PWD/portable/platform/toolchains/linux-powerpc.cmake"
cmake --build "$build" --parallel 4
ctest --test-dir "$build" --output-on-failure -j 2
```

Use `linux-i686.cmake` for i686. Cross-emulated item replay uses a base test and three actor-family batches; select `^portable_mesh_item_replay` to retain all37 families within the unchanged30-second per-test limits. Toolchains configure the CTest emulator; relocated SDKs accept `MKSC_CROSS_SYSROOT`/`MKSC_CROSS_RUNTIME` and may need host tools/libraries in PATH/LD_LIBRARY_PATH. Finished replay checks use `qemu-ppc -L RUNTIME MKSC --time-trial-finished-replay PACK INPUT COURSE DRIVER` (or `qemu-i386`).

For the browser, source Emscripten 6.0.12's `emsdk_env.sh`. Build/install SDL 3.4.18 with `emcmake cmake`, `SDL_SHARED=OFF`, `SDL_STATIC=ON`, `SDL_TEST_LIBRARY=OFF`, `SDL_TESTS=OFF`. Then configure and build the game:

```sh
build="$PWD/.mksc-tools/portable/runs/portability/web"
emcmake cmake -S portable -B "$build" -DCMAKE_BUILD_TYPE=Release -DPORTABLE_BUILD_TESTS=OFF -DPORTABLE_BUILD_SDL3_APP=ON -DPORTABLE_STRICT_WARNINGS=ON -DSDL3_DIR="$prefix/lib/cmake/SDL3"
cmake --build "$build" --parallel 4
python3 tools/portable/package_release.py --web-build "$build" --sdl-prefix "$prefix" --rom path/to/mksc.gba
python3 -m http.server 8089 --bind 127.0.0.1 --directory "$build"
```

Set `prefix` to the Emscripten SDL install before running. Open localhost and choose your owner-imported pack. The browser uses the same shell iteration and native sessions; filesystem replay/import adapters are optional. The backend boundary is described in [Architecture](ARCHITECTURE.md).

## Automated routes and scratch

For automated SDL runs set `SDL_VIDEO_DRIVER=dummy`, `SDL_AUDIO_DRIVER=dummy`, `SDL_MAC_BACKGROUND_APP=1`, `SDL_WINDOW_ACTIVATE_WHEN_SHOWN=0` and `SDL_WINDOW_ACTIVATE_WHEN_RAISED=0`. Headless runs may use every core; keep visible windows and QEMU emulation to at most two processes. `mksc --shell-smoke PACK SAVE_DIR 1` drives ordinary TT/GP menus and races; give it isolated `MKSC_DATA_DIR` and `MKSC_GP_PROGRESS` paths. `MKSC_SCREEN_DIR` captures named PPM frames, including up to eight hop-height samples per race mode. `MKSC_SHELL_CUP`/`MKSC_SHELL_TRACK` select catalog menu indices (Snow Land: 3/0); track selects TT/Quick Run, while GP begins at the cup’s first track. Replay commands verify recorded state checksums; aid completion is not a claim about human play.

The suite is deliberately lean. Pure C tests in `portable/tests/test_*.c` and the tooling tests in `tools/portable/tests` carry game rules, formats and content; they run in seconds. With `--sdl` and owner content, CTest adds one real-executable smoke route per mode or feature (first start, menu tours, TT/GP/Quick Run/Battle/VS, a Mushroom Cup, one converted 3D TT/GP/arena, course editor, mod install and Lua mods, the DS/N64 imports), not one per course, backend or setting. Add a route only for a new mode or feature; cover per-course behavior with a C test.

Converted GP checks register the four-race cup and its fresh-process reload separately, each within the existing wall-time limit; `--converted-gp-stage race|reload` selects a phase and the default `all` retains both. Reload requires the completed four-course ceremony and matching saved progress, then verifies native loading without changing the save. Converted GP verification accepts `--converted-gp-inputs=GGGJ`: four ordinary race choices, G guards inventory use, J reserves pickups and K taps items once every 120 ticks with alternating aim (live shared 3D GP only), with at least one G or K; qualification, points, grids and ceremony checks stay strict. `--converted-hold-second` remains the GJGG alias; `--converted-gp-driver 1..8` selects a stock driver through ordinary character-menu input (default2). `--converted-gp-routes auto,2,auto,auto` chooses an ordinary aid line per race; auto retains its default and Retry preserves the same request. Input aids and tours use the classic menus; `MKSC_AID_MODERN_MENUS=1` tours the modern menus at 1280×720 (`MKSC_MODERN_MENU_SIZE=WxH` overrides) and tour frames capture them. `--menu-tour` normally ignores saved settings; set `MKSC_MENU_TOUR_PERSIST_SETTINGS=1` with an isolated `MKSC_DATA_DIR` to exercise Options persistence and relaunch. Other input aids accept `MKSC_AID_PERSIST_SETTINGS=1` to load saved settings/mods for isolated real-race checks. `MKSC_MENU_TOUR_RACES=1` lets a tour enter ordinary races before continuing its menu inputs. Tour token `F` drops `MKSC_MENU_TOUR_DROP_FILE` through the normal SDL event handler for archive-install checks. `MKSC_AID_TT_SAVE_GHOST=1` drives ordinary ghost-save confirmation; `MKSC_AID_TT_RESULTS_REPLAY=1` inspects the completed results replay.
For a menu tour, `MKSC_AID_MESH_INPUTS='600:12:-32767:2;612:20:32767:1'` replaces only human0 driving controls during ordered segments: `START:COUNT:STEER:BUTTONS`, semicolon-separated, at most32 segments/4096 total turns. START is the preturn race tick including countdown (first racing input180); steering is−32767..32767 and buttons combine Accel1/Brake2/Hop4 (0 coasts). Segments apply while T/G/J/I/K pilot tokens run; gaps keep normal pilot input. Retry/course changes resample by tick, without saved state or actor targeting. Optional `MKSC_AID_MESH_INPUT_RACE=0..3` restricts these segments to that zero-based GP cup race (including Retry); it requires the segment aid and rejects non-GP use. Omission applies to all races as before. Exact admitted controls enter the ordinary replay; bounded `MKSC_AID_MESH_TRACE=START:END` reports final controls, and `3D input segment` logs each admitted start. The converted-route harness forwards `--converted-inputs` (`--converted-tt-inputs` alias) and optional GP `--converted-input-race 0..3` to this aid, requiring every selected segment's admission and no leakage to other races; `--converted-trace START:END` forwards a bounded diagnostic range; `--converted-tt-waits N` adds N ordinary90-turn waits, and repeatable `--converted-contact FAMILY` requires the existing full contact oracle before replay/relaunch acceptance. `MKSC_AID_MESH_HAZARDS=seek` (menu tours) detours human0 each lap to the nearest course actor ahead and parks where it reaches kart height until it lands a non-bump contact (900-tick cap); item presses wait until the hazard is within reach, and `3D hazard seek` logs each target; `seek:N` limits it to zero-based GP cup race N and ends it after the first contact (`seek:*` keeps every race), and a further `:FAMILY,...` (the `--converted-contact` names) narrows its targets. The converted-route harness uses it for timed or moving hazard contacts without input segments, scoped by `--converted-input-race` in a GP.


Builds, packs and ad-hoc runs belong under the ignored `.mksc-tools/portable/` folder. Never put ROM copies in the source tree.

Test-hook builds accept `MKSC_GP_DIGEST_TRACE=COURSE:TICK` (decimal tick below 60000) for GP aid diagnostics. The selected course logs cumulative typed-state hashes per accepted host tick and named hash words plus all eight racers’ before/after kinematics at the selected tick; normal builds and unset diagnostics are unchanged. 3D Time Trial and shared G/I/J tours also accept `MKSC_AID_MESH_TRACE=START:END` (decimal, inclusive, at most4096 ticks) for preturn kinematics, contact references, boost clocks, connected route cursor, inputs and bounded successor-gate geometry; it neither advances the race nor changes accepted inputs.
